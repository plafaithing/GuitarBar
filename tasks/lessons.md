## 2026-11-03 防护代码自身引入 bug（数据库只读事故复盘）

- **场景 14**：为防"启动撞锁静默只读"加的防护（setup 里 `PRAGMA user_version = 2` 写探测）本身成为事故源：每次打开强制写 header（撞锁即崩）+ 侵入 drift 自管的 schema 迁移计数。用户经历两轮"删除失败/转圈/打卡消失"，根因全是我自己的"防护"。debug 终端跑一次即实锤（Causing statement 直指防护行）。
- **规则 14**：**防护性代码与功能代码同罪同审**——加了防护更要优先怀疑防护（它跑在更早、更底层、失败半径更大）。DB 连接层的探测必须零写（BEGIN IMMEDIATE→ROLLBACK），绝不用 PRAGMA 写语句做探测，绝不碰 drift 的 user_version。

## 2026-10-29 二期设计（识谱 API）

- **场景**：二期识谱设计我默认锚定 GLM（因为用户 zai key 现成），用户纠正："未来 iOS/Windows 不能只用 glm 模型，支持可以使用其他模型"，并要求专门的模型配置页。

## 2026-10-29 二期执行（环境与代理协作）

- **场景 1**：子代理跑 `flutter pub add "image:^4.3.0"` 后 pubspec 实际写入 `image: 4.3.0`（精确 pin），`^` 在命令传参中丢失。
- **规则 1**：加依赖不使用 `flutter pub add <约束>`，直接编辑 `pubspec.yaml` 加行再 `flutter pub get`；或加完必须核对 pubspec 实际内容。
- **场景 2**：计划里给出的代码在我方（控制者）写计划时无法验证第三方包运行时行为——image 4.x 的 decodeImage 对垃圾输入抛 RangeError（Error 非 Exception）而非返回 null；drift text 模式 datetime 读裸 ISO 串会追加 Z 按 UTC 解释。
- **规则 2**：计划代码里凡调用第三方包的边界行为，都按"胶水可调"预授权并要求实现者读包源码对齐后汇报；计划文档同步在任务里写明该预授权范围。
- **场景 3**（审查侧）：质量审查对 image 包垃圾输入走哪个分支仅凭源码推断下了结论，探针实测证伪（`[1,2,3]` 同样走 catch 分支而非 null 分支）。
- **规则 3**：对第三方包边界行为的判断，探针实测优先于源码推断——写结论前先跑一次。
- **场景 4**（计划编写侧）：给"每卡独立 in-flight 态"的指令若只给单字段思路（String? _testingId），实现者会照做——单字段锁不住并发的每卡状态。计划/修复指令中涉及"N 个对象各自独立进行中"的状态，直接指名集合类型（Set）。
- **规则 4**：描述并发/多对象状态时，指令要写到数据结构层面（Set/Map per-key），不能停在"加个状态"层面——实现者会按字面执行。

## 2026-11-01 教训 4 重犯（PowerShell 管道毁文件）

- **场景 4b**：即使替换 pattern 是无操作（match 不到原文写回），`Get-Content | -replace | Set-Content` 重写 UTF-8 文件仍引入 532 个语法破坏（编码/换行损伤），且误用 `git checkout --` 回滚时把未提交的本轮编辑一并丢失，被迫完整重放。
- **规则 4（强化）**：对项目文件**任何形式**的 PowerShell 写操作（即使"只是写回原内容"）都禁止——改文件只用 Edit/Write 工具。发现管道破坏后修复顺序：先 `git diff --stat` 评估 → 只回滚确认损坏的文件 → 盘点未提交改动损失清单 → 逐项重放。

## 2026-10-30 二期走查（二进制常量）

- **场景 5**：Task 8 计划里"手写 1×1 白 PNG 字节常量"实测是坏图（image 包解码 null，API 报 1210 图片解析错误），走查第一现场暴露。
- **教训**：二进制/校验和类常量不可手编——手写 70 字节 PNG 里 IDAT CRC 等环节极易错，且测试不真解码就发现不了。
- **规则 5**：凡需要内嵌图片/二进制常量的，一律运行时用库生成（如 image 包 encodePng），或在计划中要求实现者现场生成并本地解码验证后再用；禁止在计划文档里手写字节序列。

## 2026-10-31 二期走查（跨体系弦号语义）

- **场景 6**：gpx 弦号公式 IR=gp+1 造成谱面上下镜像 + 播放音高 E2↔E4 全反（用户听感"大部分音不准"）。根因：gpif/alphaTab 的 string 1 = **最粗低音弦**，GuitarBar IR 的 string 1 = **最细高音弦**——两体系"从哪头数"相反，而参考实现（alphaTab）与目标体系（IR）的语义差异被"公式一致"的表象掩盖。正确公式 IR = 6 - gp。
- **教训**：移植外部库的格式知识时，**字段语义必须按目标体系重新核对**，不能假设编号方向一致；尤其 string/fret/track 这类"从 0 还是从 1、从高音还是从低音数"的约定，各体系传统不同（GP 系从低音数、MIDI/吉他谱惯例从高音数）。
- **规则 6**：格式移植的第一条对账断言应是**端到端音高**（弦+品+调弦 → 频率对照原版），而不是"字段值一致"——字段值一致可能掩盖语义反转。用户的耳朵是最快的仲裁者：他说"音不准+谱面反"两个症状同时出现，就该立刻怀疑弦号语义而非音色。

## 2026-10-31 走查（AI 识谱放弃决策）

- **场景 7**：AI 识谱三轮对账 7.4%→13.9%→5.6%（弦号不稳定、节奏精度不可达）；业界调研确认 OMR 全是多阶段几何流水线（视觉大模型无符干/符尾几何感知）→ 用户决策放弃 AI 通道，改纯查看器。
- **教训**：端到端对账探针（识谱 IR vs gpx 原版逐音 diff）是评估识别质量的最有效工具——三轮各 2 分钟就暴露了弦号偏移、声部丢失、节奏错误三个独立问题。
- **场景 8**：子代理 `git add -A` 把含 API key 的探针文件入库（协调者创建的探针忘了先删）。
- **规则 7**：凡创建含密钥/敏感数据的临时探针文件，协调者必须**先删再派代理**——子代理会按指令 `git add -A` 一并入库。探针文件命名统一带 `probe_` 前缀 + 结束立即删除。

## 2026-10-31 PowerShell 5.1 native 传参引号截断

- **场景 10**：`git commit -m @'...'@` here-string 提交信息含英文双引号（「12 泛音连 2 品实音」写作 "12..."），PS 5.1 向 native exe 传参时内容里的 `"` 未转义，git 收到的参数被从引号处拆断，报 pathspec 错误。
- **规则 10**：多行/含引号的提交信息一律写临时文件后 `git commit -F <file>`（用完删）；PS 5.1 native 传参不可信任何含 `"` 的内容。

## 2026-11-01 Ghidra headless 长任务（用户纠正：不要干等）

- **场景 11**：Ghidra headless 首跑即失败（`Negative delay`）——`-analysisTimeoutPerFile` 单位是**秒**，我按毫秒传 3600000 导致 int 溢出；失败后没看输出就干等完成通知，直到用户问"还在分析么"才发现。且此前两次后台任务（下载/分析）被系统内存压力静默清理，被动等通知全程黑盒。
- **规则 11**：启动长后台任务后 **1 分钟内先核验首轮日志**（参数错误/启动失败秒级暴露，确认"真的在跑"）；预计 >10 分钟的任务用 Monitor 起周期检测（进度 + 成功/失败终态全覆盖，不留静默死角），不干等通知。外部工具的长参数先查单位再传。

## 2026-11-03 重命名空格校验返工

- 错误：用户说"名字不支持空格"，我直接实现为"任意位置禁空格"，实际意图是"两侧非空、内部可空格"——返工一次（校验+测试全改）。
- 模式：**禁止性约束要确认作用域边界**（哪里禁、哪里允许），字面规则常有隐含例外。"不支持 X" ≠ "出现 X 即非法"。
- 规则：实现禁止类校验前，若作用域有多种合理解读（全局禁/局部禁/trim 即可），先用一句话向用户确认边界，或实现保守版（最小禁止范围）并在汇报里写明"当前只拦 X，需要扩到 Y 说一声"。

## 2026-11-04 关闭卡死实锤与守护误杀

- 错误链 1：「播放后关闭卡死」最初以为是打卡挂——close-log.txt（关闭步骤打点落盘）实锤 exit(0) 已调用、进程仍不死：**exit() 的 C 终止序列本身挂死**（soloud 播放后 native 清理钩子死锁）。现场佐证：taskkill /F 都杀不动的僵尸（"no running instance"却还在进程表）。
- 错误链 2：守护 v1 做成常驻心跳（0.7s ping 主线程），把**启动时 5s 同步初始化段**误判为卡死，刚启动的应用被强杀——用户"打开后自己就关了"。
- 规则 15：**关闭类守护必须"事件武装"**（收到关闭信号才开始计时强杀），不做常驻心跳——常驻心跳无法区分"卡死"与"合法的长同步段"（启动初始化/渲染）。
- 规则 16：**dart:io exit() 不保证终止进程**（native atexit 可挂）——必须死的场景用 TerminateProcess（lib/core/hard_exit.dart）。
- 方法论：关闭路径从第一天就打点落盘日志，本次实锤全靠它；"async/timeout 守卫"只保护 Dart 层，跨 FFI/native 边界的挂死要换武器。
