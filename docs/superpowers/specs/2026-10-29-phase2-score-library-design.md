# GuitarBar 二期设计：曲谱库 + 识谱 + 自动演奏

> 2026-10-29 brainstorming 定稿。一期（练琴工具箱）已收官，本文档为二期唯一设计依据。
> 上游依据：一期设计文档第 2 节路线表（2026-10-23）。

## 1. 背景与目标

用户的曲谱存量**以图片和 PDF 为主**（gp5 少量）。二期把"看谱练琴"搬进 GuitarBar：

1. **曲谱库**：图片/PDF 导入归档，随时打开
2. **识谱**：AI 视觉模型把谱面转成结构化曲谱数据（IR）
3. **自动演奏**：解析后的曲谱直接播放（合成音）
4. **跟练三件套**：变速、AB 循环、多音轨（2026-10-25 竞品调研确认，参考恩雅音乐）
5. **练习录音回放**、**升降调/移调**（低优先级保留）

成功标准：导入一份图片/PDF 曲谱 → 识谱入库 → 直接播放跟练，全程无需逐音校对。

**定位原则（2026-10-29 用户确认）**：曲谱库首先是**源文件仓库**——导入即归档即查看，
未识谱的条目直接打开原图/PDF 看（纯查看器，零编辑零识别）；识谱与自动演奏是
叠加在其上的增强层，不是使用的前提。

## 2. 范围

**做**：图片/PDF 导入、AI 识谱（OpenAI 兼容协议、模型无关）、六线谱渲染视图、自动演奏、
变速/AB/多轨、置信度标记、点选修正（听觉校对的编辑入口）、交叉验证（防护工具）、
练习录音回放、升降调/移调、MusicXML/gp5/MIDI 导入（辅助）。

**不做**：强制逐音校对界面（用户明确拒绝——太花时间）、云端同步、谱面重排版、
扫弦/闷轮指等高级技法的音色仿真（v1 降级为近似处理）。

## 3. 架构总览

```
曲谱来源                 识谱管线                 消费端
────────────           ─────────────           ─────────────
图片 ─────────┐        PDF → 逐页转图          六线谱渲染视图
PDF ──────────┼──→     ↓                       （置信度标记/点选修正）
gp5/MusicXML/MIDI ─┐   视觉 API (GLM)          ↓
                   │   ↓                       自动演奏
                   │   结构化 JSON              （变速/AB/多轨）
                   │   ↓                       ↓
                   └─→ 统一 IR ←──────────      练习录音回放
                       （schema 校验）
                       ↓
                       drift 曲谱表 + 原谱文件
```

三块边界：**识谱管线**只负责"来源 → IR"；**曲谱库**负责存储与浏览；**演奏端**只消费 IR，
不知道来源。各块可独立测试。

## 4. 统一曲谱 IR（核心数据模型）

所有来源归一。JSON 形态（存储与传输同构）：

```json
{
  "version": 1,
  "title": "曲名",
  "tempo": 90,
  "timeSignature": "4/4",
  "tuning": ["E2", "A2", "D3", "G3", "B3", "E4"],
  "capo": 0,
  "tracks": [
    {
      "name": "主旋律",
      "measures": [
        {
          "index": 0,
          "confidence": 0.92,
          "failed": false,
          "notes": [
            { "beat": 0.0, "duration": 1.0, "string": 1, "fret": 3,
              "technique": null, "confidence": 0.95 }
          ]
        }
      ]
    }
  ],
  "unrecognizedPages": []
}
```

约定：

- `string`：1-6，1 = 最高音弦；`fret`：0 = 空弦
- `beat`/`duration`：以拍为单位（随 tempo 换算秒）
- `technique`：v1 识别不到为 null；已定义枚举 h/p/s/b/H（击/勾/滑/弯/闷/**自然泛音**），
  闷音演奏时降衰减，泛音演奏时按谐波近似（2026-10-29 真实谱面校准：用户谱例泛音
  `<12>` `<16>` 记号密集，必须有独立记号，否则播放八度错误）；渲染 v1 对 H 先按
  弦品音高近似（12 品泛音恰对，5/7 品略偏），真谐波音色 M5+ 评估
- `confidence`：小节级与音符级都有；null 表示非 AI 来源（确定性导入无此概念）
- `failed`：true = 该小节识别失败（页失败占位或机器校验不过），notes 恒为空数组——
  可见化不静默丢（§9）；顶层另有 `unrecognizedPages: [页号]` 汇总失败的页
- **变速不改 IR**（见 §7），`capo` 与升降调作为演奏时偏移，不回写音符

## 5. 识谱管线

### 5.1 输入处理

- **PDF**：pdfium 逐页渲染为 PNG（200-300 DPI）
- **图片**：直接使用（超大图先等比缩到长边 ≤4096px）；**支持按文件夹导入**——
  选一个文件夹，其中的图片（按文件名排序）合成一份多页曲谱
  （2026-10-29 用户确认：多图曲谱以文件夹形式存放，如"Like a star谱例"5 张 JPG），
  导入 UI 提供"导入文件/导入文件夹"两个入口
- **gp5/MusicXML/MIDI**（辅助路径）：本地确定性解析 → IR，不走 AI、无 confidence

### 5.2 视觉识别（OpenAI 兼容协议，模型无关）

- **协议**：OpenAI 兼容 chat-completions（vision message）——一个协议覆盖智谱 GLM、
  OpenAI、DeepSeek、硅基流动、Ollama 等主流/本地模型，**不绑定任何厂商**
  （2026-10-29 用户确认：未来 iOS 端不能只用 GLM，须支持其他模型）
- **模型配置页**（见 §8）：多套配置可存（名称/base URL/API Key/模型名），单套启用，
  内置智谱预设模板；配"测试连接"按钮（发一张内置测试图验证连通与识别返回）
- **Prompt 策略**：要求输出与 §4 同构的 JSON，逐小节自报 confidence，
  低置信度定义：拍弦/密集和弦/复杂指法区；**prompt 必须携带调弦与变调夹**
  （2026-10-29 真实谱面校准：用户谱例全部带自定义调弦+capo，如 C G D G A D
  Capo=2、Drop D Capo 3f），品位数字按夹后计
- **真实谱面实测校准（2026-10-29）**：用户谱库两类形态——①风格化六线谱
  （数字谱样式、角括号泛音、水印覆盖、附视奏顺序图）②五线谱+TAB 双轨
  （节奏看五线谱、位置看 TAB、P/S 字母技法）。真实 PDF（含 9MB 扫描件）经
  PdfRasterizer 200DPI 逐页转 PNG 探针通过、目检清晰够用
- **GLM 视觉探针实测（2026-10-29，真实谱例）**：结构化 JSON 输出 schema 完全
  conform、泛音 `<n>` 识别为 H 技法、置信度诚实自报（复杂小节 0.3-0.4）——
  识谱管线核心假设成立。**延迟校准**：thinking 模式下单次调用分钟级
  （2 小节约 8-10 分钟）→ 识谱调用的超时须放宽到 10 分钟级（与测试连接的
  15s 分开配置），逐页进度 UI 必要；max_tokens 8192 整页可能截断，截断走
  重试→失败页标记路径，实测后再调
- **响应机器校验**（零成本防线）：JSON schema 校验 + 合理性检查
  （弦 1-6、品 0-24、beat 单调、duration > 0）；不合规格的小节整体标记为"未识别"，
  不静默丢弃
- **重试**：单页失败重试 1 次，仍失败则该页标记未识别，其余页正常入库

### 5.3 校对策略（2026-10-29 用户确认）

**零校对直入库**。质量保障三层：

1. **听觉校对（主）**：自动演奏即校对工具——播放时对照原谱图听，出错的小节
   点选修正。修正发生在"听"和"练"的过程中，无额外时间成本。
2. **置信度标记（辅）**：低置信度小节在曲谱视图上轻标记（不阻塞、不强制），
   听到不对劲时优先怀疑这些位置。
3. **交叉验证（最后防护手段）**：同一页跑两次识别，diff 结果——一致小节视为可靠，
   不一致小节标记供重点核对。**默认不启用**（双倍费用），用户手动触发，
   服务于耳朵没把握的场景（不熟的曲子、复杂谱）。

点选修正交互：小节点开 → 弦/品/时值快捷编辑 → 保存回写 IR（confidence 置 1，
表示人工确认）。**v1 边界（2026-10-30 审查确认）**：cleared 空小节无 add-note
路径（音符补录留后续版本，clear 后 SnackBar 反馈口径），时值不得溢出小节
（弹层禁用超限 chip）；识谱进行中禁编辑（防覆盖刚完成的识别结果）。

### 5.4 竞品参考（Tabtify，2026-10-29 调研）

Tabtify（tabtify.com）在做同一条管线：PDF/照片 → AI 可编辑 tab → 回放+逐小节循环
校正（check by ear）→ 导出 GP5/MIDI/MusicXML——**与本设计（§5.3 听觉校对+点选修正）
同构，方向得到商业产品验证**。其公开的能力边界用于校准我们的预期：

- **技法（推弦/滑音/击勾弦）不随识别保留**，只保音符+节奏 → v1 识谱硬指标定为
  音符+节奏，技法 best-effort（识别不出即 null，与 §4 一致）
- 反复记号按印刷样式带一遍不展开；歌词与和弦名丢弃
- 手写谱、模糊印刷错音率高；原始 PDF 优于翻拍照片
- 单次最多 8 页 / 20MB → 我们逐页处理，天然无此上限

不做集成（外部在线服务，且用户已确认外部手动转换流程太麻烦）。

## 6. 数据层

- **drift 新表 `scores`**：id、title、sourceType（image/pdf/gp5/musicxml/midi）、
  tempo、tuning、irJson（TEXT）、sourcePath（原谱文件相对路径，可空）、
  createdAt、updatedAt
- **原谱文件**：应用支持目录 `scores/<id>/` 下存原图或 PDF 逐页 PNG
  （与 SQLite 同目录——2026-10-29 审查定案：备份通道与数据文件同根，不用文档目录）
- **导出/导入**：二期备份格式升级为 **zip**（manifest.json + 曲谱 IR + 原谱文件）；
  一期纯 JSON 备份保持不动（无曲谱时 zip 退化为 manifest + JSON，双向兼容不强行做）

## 7. 自动演奏与跟练

### 7.1 渲染式播放（核心决策）

**整曲离线渲染为 PCM，再播放**——复用一期已验证的两条管线：

- 音色：Karplus-Strong 拨弦合成（一期 pluck），按音符频率触发叠加进时间线 buffer
- 时间调度：MetronomeEngine 的采样精确时间线思路（beat → sample offset）

选渲染而非实时调度的理由：无调度抖动、变速免费且**无音调失真**、AB 循环只是
buffer 区间参数、多轨就是分 buffer 混音。代价是改谱后需重渲染（秒级，可接受）。

### 7.2 跟练三件套

| 功能 | 实现 |
|---|---|
| **变速** | 按速度系数**重渲染**时间线（tempo 缩放 beat→sample 换算），音高不变、节奏变 |
| **AB 循环** | 渲染 buffer 的起止 sample 对（按小节选），播放区间循环 |
| **多音轨** | 每轨独立 buffer，播放时按轨混音；支持静音/独奏；限幅防爆音 |

### 7.3 升降调/移调（低优先级）

演奏时音符偏移（半音数）与变调夹（capo）位置，均为渲染参数，不动 IR。

## 8. UI 结构

- **导航不变**：3 tab 与一期各页零改动；**二期全部能力从工具箱进入，一行一工具**
  （2026-10-29 用户确认）。M1-M4 单入口"曲谱库"行——识谱/播放都是对某份谱的动作，
  拆独立行会失去对象上下文；M5 跟练三件套落地后若体感笨重，再拆独立"跟练台"行
  （遗留决策点 §12）
- **曲谱库页**：列表（曲名/来源类型/页数/识谱状态——M1 阶段调弦恒空故不显示，
  M2 接线后评估是否加回调弦列）+ 导入按钮（图片/PDF/文件）+ 识谱进度
- **曲谱详情页**：宽屏谱面与原图并排、窄屏切换；六线谱横向滚动；
  播放控制条（播放/变速/AB/音轨开关）；小节点选编辑弹层。
  **未识谱条目只有原图/PDF 纯查看器**（交互对照比对只在需要时用，平时看谱
  就是直接翻源文件，无任何编辑与研究负担）
- **模型配置页**（个人中心 → 识谱模型）：配置卡片列表（名称、base URL、API Key、
  模型名），可增删改、单选启用；内置智谱预设模板；每张卡带"测试连接"；
  配置存 settings 表（JSON），key 本地存储不上传

设计语言沿用 achromatic-ledger：谱面线/字用 ink/muted，音符与置信度标记用 dataHue，
低置信度标记为 dataHue 低透明度，播放头用 positive 绿。（2026-10-30 口径确认：
六线谱**品数字用 ink**——数字是内容主体而非数据标记；dataHue 仅上低置信度底）

> **2026-10-31 更新**：识谱 UI 入口随 13.4 决策移除（AI 通道放弃）；
> 本节的谱面视图/置信度/编辑设计仅服务于 GTP 导入数据。

## 9. 错误处理

- API 失败/超时：单页重试 1 次 → 标记未识别，不阻塞其余页；模型未配置引导去模型配置页
- 机器校验不过：整小节"未识别"标记（可见化，不静默丢）
- 渲染失败（极端 IR）：报告小节号，跳过该小节继续
- 大 PDF：逐页处理 + 进度显示，可取消
- 录音失败：跟练不受影响，录音为旁路

## 10. 测试策略

- IR schema 校验与归一化：纯函数单测（含非法输入矩阵）
- GLM 响应 → IR：fixture JSON 离线单测（不依赖网络）
- PDF 转图：Windows 集成测试
- 时间线渲染：音符起始 sample、混音叠加、变速缩放、AB 区间——单测锚定
- 交叉验证 diff：单测
- gp5/MusicXML 解析：fixture 单测（M6）
- UI：沿用一期手工验收 + 走查模式

## 11. 里程碑

| 阶段 | 内容 | 出口标准 |
|---|---|---|
| M1 | 曲谱库骨架：导入图片/PDF、归档列表、原图查看 | 一份 PDF 从导入到可见 |
| M2 | 识谱管线：转图 + 视觉模型 + IR 归一 + 入库 | 一份图片谱识出 IR 入库 |
| M3 | 曲谱视图：六线谱渲染 + 置信度标记 + 点选修正 | 谱面与原图对照可读可改 |
| M4 | 自动演奏：IR → PCM 渲染 → 播放 | 播放可听，听觉校对闭环成立 |
| M5 | 跟练三件套：变速 + AB + 多轨 | 慢速循环跟练可用 |
| M6 | 交叉验证防护工具 | diff 标记不一致小节 |
| M7 | 辅助：MusicXML/gp5/MIDI 导入、录音回放、升降调 | 按优先级逐项 |

M1-M4 是主线（识谱到能听）；M5 交付跟练体验；M6/M7 按需。

## 12. 遗留决策点

- 默认识谱模型：M2 实测 glm-4v-flash（免费）与 glm-4.5v 的识别质量后定；
  协议已模型无关，换厂商只改配置
- "跟练台"是否拆为工具箱独立行：M5 落地后按体感决定
- 高级技法音色（h/p/s/b 的真实听感）：v1 近似，实测后评估是否深化
- zip 备份与一期 JSON 备份的合并策略：M7 时定

## 13. 二期追加任务（2026-10-30 用户提出，排在 M7 后或 M5-M7 期间）

### 13.1 和弦库分类浏览（新手查阅能力）

现状：和弦库是"自行输入和弦名 → 算法生成指法"，对没记住和弦名的新手不友好。
增加**分类浏览**路径：

- **分类树**：三和弦（大三/小三/增三/减三）→ 七和弦（大七/小七/属七/半减七/减七…）
  → 挂留（sus2/sus4）→ 加音（add9 等）——分类下枚举具体和弦
- **交互**：分类 → 子类 → 和弦列表 → 点选 → 按弦位置（指法图 + 试听，
  复用一期 ChordParser/FingeringGenerator——浏览只是把"输入"换成"枚举点选"，
  生成引擎不变）
- 浏览枚举需根音选择（12 音）× 调弦联动（随当前调弦生成指法，与一期一致）

## 13.4 AI 识谱通道放弃，转纯查看器（2026-10-31 走查决策）

三轮端到端对账（匹配率 7.4%→13.9%→5.6%，弦号不稳定、节奏精度不可达）+
业界调研（OMR 全是多阶段几何流水线，视觉大模型无符干/符尾几何感知）：
**AI 识谱通道正式放弃**。识谱相关代码保留（调弦/capo 识别、校验器、置信度
标记未来可复用），但 UI 入口移除。曲谱通道二选一：

- **GTP（.gpx）导入**：精确数据 → 谱面 + 播放（现有能力保留）
- **图片/PDF：纯查看器**（不再识谱）——增强交互对齐主流看图体验

### 查看器交互规格（用户指定，全平台）

| 操作 | Windows | iOS |
|---|---|---|
| 翻页 | **鼠标滚轮**（垂直滚轮→水平翻页）或横拖 | **单指横拉** |
| 缩放 | **鼠标滚轮 + Ctrl** 或双击 | **双指捏合** |

### GTP 展示界面调整

- 删除右侧源文件（原图）面板——**全界面显示谱面**（GTP 导入无页图，
  现在右侧显示"没有页图"空态，无意义）
